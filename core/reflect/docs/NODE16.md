# Node 1.6 reflection demo

## Program contract

`reflect_demo` accepts exactly one mode, with no defaults:

| Flag | Values |
| --- | --- |
| `--expect-schema` | `<Type> <file>` |
| `--expect-inspector` | `<Type> <file>` |
| `--roundtrip` | `<Type> <file>` |
| `--load` | `<Type> <file>` |
| `--script` | `<file> <expected-file>` |
| `--glue-proof` | none |
| `--watch` | none |
| `--inject-fault` | none |

Types are `Vehicle` and `Wheel`. Files are relative to the crate folder
`core/reflect`, not the shell's working directory. Only normal path components
are accepted: no root, drive, empty component, `.` or `..`; both slash styles
are checked. Control characters are rejected. Values beginning `--` are not
accepted. Unknown flags, incorrect arity and multiple modes are usage errors.

Exit codes are 0 (PASS), 1 (FAIL), and 2 (usage error, never a silent skip).
A usage error writes one stderr line `reflect_demo: usage: <message>` and no
stdout. Non-UTF-8 command-line arguments are usage errors.
Unreadable fixtures are usage errors naming the file.

The parsed but unavailable modes return 2 with these exact stderr lines:

```text
reflect_demo: usage: --roundtrip is not implemented yet (R9b)
reflect_demo: usage: --load is not implemented yet (R9b)
reflect_demo: usage: --script is not implemented yet (R9b)
reflect_demo: usage: --glue-proof is not implemented yet (R10)
reflect_demo: usage: --watch is not implemented yet (R10)
reflect_demo: usage: --inject-fault is not implemented yet (R10)
```

Done-check command form, from the Broadsword root (run by the orchestrator):
`build/bin/broadsword.exe run forge -- cargo run --offline --release -p reflect --example reflect_demo -- <flags>`.
Task verification adds `--task t-20261124-185600` after `forge`.
The demo reads fixtures as bytes and never writes files.

## Schema text

The authoritative writer is `schema::schema_text`; `schema::schema_hash`
computes FNV-1a 64 over exactly those bytes.

1. Lines end with LF, including the last line; items use single spaces.
2. The header is `reflect schema 1`.
3. Type blocks are root-first, depth-first, with equal named types emitted
   once. Conflicting descriptors sharing a name are errors.
4. Each block begins `type Name version=V fields=N` and ends `end`.
5. Fields follow descriptor order. Each line writes `field <name> kind=<kind>
   since=<version>`, followed by present metadata in order: label, unit, min,
   max, readonly, hidden, default, renamed_from.
6. Scalar kinds use lowercase names; containers use `list<K>`, `array<K;N>`,
   `option<K>`, structures `struct<Name>`, enums `enum<Name:V1|V2>`.
7. Floats use `0x` and sixteen lowercase hexadecimal bit-pattern digits;
   integers use decimal. Quoted UTF-8 strings escape backslash, quote, LF,
   CR and TAB; other controls use `\u{hex}`.
8. Defaults use comma-separated `[]` lists and `{}` structures, `none` or
   `some(v)` options, `true`/`false` booleans and bare enum variants.

The hand-worked example is [vehicle.schema.txt](../fixtures/vehicle.schema.txt),
transcribed from the brief, not generated by the demo. It describes Vehicle
then Wheel; Vehicle's drive is since 2 with default Rear, and mass_kg is
renamed from mass. Its expected FNV-1a 64 is `8b1bd5d2c9f51001`.
These are fixed reference bytes, not files to regenerate after a mismatch.

## Inspector text

The authoritative writer is `inspector::to_text`; the count comes from
`inspector::widgets`, not from the expected file.

1. Emit one LF-terminated `widget` line per visible field in depth-first order.
   Hidden fields and their descendants are omitted.
2. Items are path, kind, quoted label, then present unit, min, max, of, len,
   variants and readonly. Labels fall back to field names. Quoting escapes
   backslash and double quote; numbers use Rust's Display format.
3. Lists and arrays have `of=<element kind>`; arrays also have `len=<length>`.
   Scalar list/array elements have a representative `[0]` row labelled
   `<label> item` with the field's unit and range.
4. Struct descendants use dotted paths. List/array struct fields are under
   `<path>[0].`; optional structs have descendants under `<path>.`.
   Optional scalars have no element row.
5. Enum variants are joined by `|`; readonly is inherited by descendants.

The hand-worked example is
[vehicle.inspector.txt](../fixtures/vehicle.inspector.txt), transcribed from
the brief. The position array has a `position[0]` element row, and wheels has
its three Wheel fields under `wheels[0].`. No sample values are read.

## Output lines

Successful comparisons write exactly one stdout line:

```text
schema Vehicle version=2 fields=6 hash=8b1bd5d2c9f51001 expected=fixtures/vehicle.schema.txt result=PASS
inspect Vehicle widgets=10 expected=fixtures/vehicle.inspector.txt result=PASS
```

Generally the forms are `schema <Type> version=<v> fields=<n> hash=<16 lowercase
hex digits> expected=<file as given> result=PASS` and
`inspect <Type> widgets=<n> expected=<file as given> result=PASS`.
On mismatch the same line ends `result=FAIL`, followed by `diff line=<k>`.
The line number is one-based and identifies the first differing line, including
a missing or extra line. A line includes its LF; a final piece without LF is
also a line. No trimming or line-ending normalization occurs. Empty fixtures,
CRLF, changed bytes and missing final LF therefore fail.

Schema generation errors write `reflect_demo: FAIL schema <error>` to stderr
and return 1. Output write failures return 1 and attempt a stderr diagnostic.
